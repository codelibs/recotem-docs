# Recotem docs — SEO foundation + bilingual content design

Date: 2026-07-09
Status: Phase A implemented; Phases B–D pending.

## Goal

Grow organic discovery of Recotem by (1) adding a technical-SEO foundation to
the VitePress site so every page (existing and new) is indexable and
share-ready in both English and Japanese, and (2) adding a bilingual set of
search-intent-driven content pages under a new `Learn` section.

Non-goals: changing `guide/` / `docs/` structure, touching archived `1.0/`
content, analytics/Search-Console wiring (deferred — needs account IDs).

## Approach

Foundation-first. The technical SEO layer is one small, self-contained change
that lifts the whole site, so it ships before the content. Content is then
added as pillar → cluster clusters that cross-link to each other and to the
existing `guide/` / `docs/` pages.

Because the content set is large (~14 pages × 2 languages), implementation is
split into phases, each its own PR.

## Phase A — SEO foundation (this PR)

All page-level SEO is generated centrally by a single `transformPageData` hook
in `.vitepress/config.ts`, so content pages need no per-page boilerplate.

Per page (all non-`1.0/` pages):
- `<link rel="canonical">` — self-referential, matches the default
  (`cleanUrls: false`) URL scheme so canonical / hreflang / og:url / sitemap
  all agree.
- hreflang alternates — `en`, `ja`, and `x-default` linking each EN `/x` to its
  JA `/ja/x` counterpart (v2 trees are fully mirrored).
- Open Graph — `og:site_name`, `og:type` (`website` for home, `article`
  otherwise), `og:title`, `og:description`, `og:url`, `og:image`, `og:locale`
  (+ alternate).
- Twitter — `summary_large_image` card with title/description/image.
- JSON-LD — home emits `Organization` + `WebSite` + `SoftwareApplication`
  (free, Apache-2.0); content pages emit `TechArticle`.

`1.0/` archive pages get a self-canonical only (no bilingual pairing).

Supporting changes:
- Per-locale site `description` (EN/JA) → VitePress emits `<meta name=description>`
  for any page without frontmatter `description`.
- `public/robots.txt` — allow all + `Sitemap:` line.
- `public/og-image.png` (1200×630) — default social card, generated by
  `scripts/make_og_image.py` (Pillow only, reproducible).
- Backfill `description` frontmatter on the 15 core `docs/*` pages (EN) and
  their 15 `ja/docs/*` mirrors (guide pages already had descriptions).
- `srcExclude: ['specs/**', 'scripts/**']` so this spec and the generator are
  tracked but not published.

Sitemap generation was already enabled (`sitemap.hostname`); new pages appear
automatically.

## Conventions & risks

- **Keyword cannibalisation**: `use-cases/ga4-bigquery` vs existing
  `docs/data-sources/bigquery.md` (goal-oriented tutorial vs source reference)
  and `use-cases/purchase-logs` vs `guide/tutorial` (SEO landing vs official
  getting-started). Differentiate intent and cross-link; keep self-canonicals.
- **Comparison pages** (P1–P3) must be factual, fair, and non-disparaging;
  verify claims about other projects/services before publishing.
- Every new page ships EN + JA together and is registered in the sidebar helper
  (unregistered pages become orphaned, as the legacy `docs/user/*` pages are).
- Internal linking: pillar ↔ cluster, and each Learn page → relevant
  `guide/` / `docs/` reference page, to distribute authority to existing pages.
