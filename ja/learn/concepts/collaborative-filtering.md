# 協調フィルタリングとは

**協調フィルタリング（Collaborative Filtering, CF）** は、「この商品を買った人はこ
れも買っています」「あなたに似たユーザーはこれも見ています」を支える定番手法で
す。アイテムが _何であるか_（ジャンル・価格・説明文）を分析するのではなく、
_行動_ から学習します。すなわち「誰が何に触れたか」というパターンです。2 人が同じ
商品を数多く買っていれば、一方が買ってもう一方がまだ見ていないものは、有力なおす
すめ候補になります。この単純な発想を数百万のユーザーとアイテムに適用したものが、
日々目にするパーソナライズ推薦のほとんどを動かしています。

このページでは、CF の仕組み、主要なアルゴリズムの分類、それぞれが苦手とする場面、
そして [Recotem](/ja/learn/) がどれを提供しているかを解説します。推薦手法の全体像
については [レコメンドシステムとは](/ja/learn/concepts/recommendation-system) を参
照してください。

## 基本的な考え方

協調フィルタリングは、たった 1 つのデータ構造から出発します。**ユーザー×アイテム
の相互作用行列**です。行がユーザー、列がアイテムで、あるユーザーがアイテムに触れた
（購入・クリック・再生・評価した）ときにセルが埋まります。この行列はほぼ必ず _疎_
です。どのユーザーもカタログのごく一部にしか触れていないため、圧倒的多数のセルは
空のままです。

レコメンダーの仕事は、その空セルのうちどれを埋めるべきかを予測することです。アイテ
ムのタイトルやカテゴリは一切読まず、相互作用の形だけを見ます。「協調」という名前は
その仕組みを表しています。ユーザーは行動の痕跡を残すことで暗黙的に協力し合い、各
ユーザーは似た行動をした全員の痕跡から恩恵を受けるのです。

CF はアイテムの内容を完全に無視するため、明確な長所と短所があります。長所は、
コンテンツベースの手法では決して結びつけられない、意外でカテゴリを横断した推薦を
掘り起こせること。「このドリルを買った人はこの特定のコーヒーも買う」という古典的な
例です。短所は、人々が触れ始めるまでアイテムについて何も分からないことです。

## 直感をつかむ例

4 人のユーザーと 5 本の映画を考えます。チェックはそのユーザーが視聴したことを表しま
す。

| ユーザー | ヒート | カジノ | マトリックス | インセプション | アメリ |
|------|:----:|:------:|:----------:|:---------:|:------:|
| Ana  | ○    | ○      | ○          |           |        |
| Ben  | ○    | ○      |            |           |        |
| Cara |      |        | ○          | ○         |        |
| Dan  |      |        |            |           | ○      |

**Ben** には何をおすすめすべきでしょうか。Ben は『ヒート』と『カジノ』を見ていま
す。Ana はその 2 本に加えて『マトリックス』も見ています。Ana と Ben は大きく重なる
ため、Ana は Ben の最近傍ユーザーです。そこで Ben への自然な提案は、Ana が好んで
Ben がまだ見ていない作品、すなわち **『マトリックス』** になります。

ここで使わなかったものに注目してください。ジャンルも監督もあらすじも使っていませ
ん。共起を数えただけです。これが協調フィルタリングの縮図です。誰とも作品を共有しな
い Dan は難しいケースで、後述するコールドスタート問題そのものです。

## ユーザーベース vs アイテムベース

この行列は、対称的な 2 つの読み方ができます。

- **ユーザーベース CF** は「誰が自分に似ているか」に答えます。あなたと相互作用履歴
  が似たユーザーを探し、その近傍ユーザーが好んで、あなたがまだ見ていないアイテムを
  推薦します。上の例はユーザーベースです。Ana が Ben に似ていると分かり、Ana の
  「余分な」作品を借りてきました。
- **アイテムベース CF** は「自分が好んだものに似ているのは何か」に答えます。行列の
  列から _アイテム同士の類似度_ を計算し（同じユーザーが両方に触れやすいほど似てい
  る）、あなたが既に接したアイテムに似たものを推薦します。この例では、Ana と Ben が
  ともに視聴したことで『ヒート』と『カジノ』が似ているとみなされ、『ヒート』のファ
  ンに『カジノ』が提示されます。

アイテムベース CF が業界の定番になったのには実用的な理由があります。多くのカタログ
では、アイテム間の関係はユーザー間の関係よりはるかに安定しているのです。ユーザーの
嗜好は週ごとに変わりますが、2 つの商品がよく一緒に買われるという事実は変わりませ
ん。アイテム間類似度行列は事前計算して再利用できるため、アイテムベース CF は大規模
配信でも高速です。

## メモリベース vs モデルベース

もう 1 つの、より重要な軸は、_どのように_ 類似度を計算するかです。

### メモリベース（近傍法）

メモリベース CF は生の行列を直接扱います。行同士（ユーザーベース）または列同士
（アイテムベース）の類似度スコア（古典的にはコサイン類似度）を計算し、各アイテム・
ユーザーの最近傍を保持し、近傍が好んだものの重み付き平均として推薦を生成します。機
械学習的な意味での「学習」はなく、モデルとは蓄えた行列と類似度関数そのものです。近
傍法は透明性が高く（「X を見たのでおすすめ」と説明しやすい）理解しやすい一方、ペア
ごとの類似度計算は高コストになりがちで、概念的に関連していても一度も共起しないアイ
テム同士へは一般化しづらいという弱点があります。

### モデルベース（行列分解・iALS）

モデルベース CF は、観測された相互作用を _説明_ し、未観測のものを予測できる、コン
パクトな統計モデルを学習します。中心となるのが **行列分解（Matrix Factorization,
MF）** です。各ユーザーと各アイテムを、隠れた要因からなる短いベクトル（_潜在埋め込
み_）で表現でき、ユーザーのアイテムへの選好は 2 つのベクトルの内積で表せる、と仮定
します。学習は、既知の相互作用を最もよく再現する埋め込みを見つけます。

これらの潜在要因はラベル付けされたものではなく学習されたものですが、しばしば認識可
能な概念と対応します。ある次元が「アクションの激しさ」や「アートハウス志向」を表す
ようになる、といった具合です。多くのユーザーが同じように扱うアイテム同士は潜在空間
で近くに配置されます。_1 人のユーザーも両方に触れていなくても_ です。だからこそ行列
分解は、生の近傍カウントより遠くまで一般化します。

行動データにとって最も重要な MF の変種が **implicit Alternating Least Squares
（iALS）** です。通常の MF は明示的な星評価向けに設計されており、空セルは「未評価」
を意味します。しかしクリックや購入は正のシグナルしか与えません。空セルは曖昧です
（嫌いだったのか、単に見ていないだけなのか）。iALS はすべての相互作用を _信頼度で
重み付けした正例_ として扱い、空欄を弱い負例とみなし、ユーザー要因とアイテム要因を
交互に閉形式で解いて収束させることでこれに対処します。暗黙的シグナルと明示的シグナ
ルの違いは重要なので、専用ページ [暗黙的・明示的フィードバック](/ja/learn/concepts/implicit-explicit-feedback)
を用意しています。

## コールドスタート問題

純粋な協調フィルタリングには、構造的な盲点が 1 つあります。動作するには相互作用履歴
が必要だということです。これは **コールドスタート問題** として、3 つの形で現れま
す。

- **新規アイテム。** 誰も触れていないアイテムは列が空なので、CF は比較する材料を持
  たず、決して推薦されません。新しい在庫にとっての鶏と卵のジレンマです。
- **新規ユーザー。** 履歴のないユーザー（上の Dan）は行が空で、借りてくる近傍があり
  ません。通常は十分なシグナルが貯まるまで、非パーソナライズの人気度にフォールバッ
  クします。
- **疎なテール。** 定着したユーザーやロングテールのアイテムでも、相互作用がわずかし
  かなければ、ノイズが多く信頼度の低い推薦になります。

一般的な緩和策は、**コンテンツベース**のシグナル（新規アイテムを _説明できる_ アイ
テムメタデータ）を混ぜて **ハイブリッド** レコメンダーにすることと、まだパーソナラ
イズできない相手には **人気度ベースライン** を提示することです。良い人気度フォール
バックは妥協案ではありません。まっさらな新規ユーザーにとっては、しばしば最も強い提
示内容になります。

## Recotem における協調フィルタリング

Recotem は [irspack](https://github.com/tohtsky/irspack) の上に構築されており、学習
するアルゴリズムはすべて相互作用行列に対する協調フィルタリングモデルです。上記のど
れも自分で実装する必要はありません。レシピに候補アルゴリズムを列挙し、チューニング
済みの探索に勝者を選ばせます。ここで特に関連が深い CF アルゴリズムは次のとおりで
す。

- **`IALS`** — 上で説明したモデルベースの行列分解、implicit Alternating Least
  Squares です。信頼度で重み付けした暗黙的シグナルから、潜在的なユーザー・アイテム
  埋め込みを学習します。クリック・購入データに対する汎用的な第一候補として、たいて
  い最も強力です。
- **`CosineKNN`** — アイテムベースかつメモリベースの CF。相互作用の列に対するコサイ
  ン類似度でアイテム間類似度行列を構築し、あなたが接したものに最も近いアイテムを推
  薦します。透明性が高く、信頼できるベースラインです（エイリアス `CosinekNN` も受け
  付けます）。
- **`RP3beta`** — グラフベースの近傍法。ユーザー×アイテム行列を二部グラフとみなし、
  3 ステップのランダムウォーク遷移確率でアイテムをスコアリングします。`beta` 項が人
  気アイテムにペナルティを与え、推薦が話題作に偏りすぎないようにします。疎な暗黙的
  データでは、素朴なコサイン KNN を上回ることがよくあります。
- **`TopPop`** — 一切パーソナライズしませんが、あらゆる CF システムがコールドスター
  トのユーザー向けに必要とする人気度ベースラインです。候補に含めておくと、探索が越
  えるべき正直な下限が得られます。

Recotem は 1 つに絞ることを強制しません。複数を列挙すれば、Recotem が
[Optuna](https://optuna.org/) による複数アルゴリズム探索を実行し、それぞれをチュー
ニングして、選んだ [評価指標](/ja/learn/concepts/evaluation-metrics) で最も高いスコ
アのモデルを残します。

```yaml
training:
  algorithms: [IALS, CosineKNN, RP3beta, TopPop]
  metric: ndcg
  cutoff: 20
  n_trials: 40
```

普遍的に最良のレコメンダーは存在しないため、行列分解モデル（`IALS`）、2 つの近傍法
（`CosineKNN`、`RP3beta`）、人気度ベースライン（`TopPop`）を 1 回の探索で比較するの
はまさに正しい発想です。直感ではなく検証指標が勝者を決めます。受け付けるアルゴリズ
ム名の完全な一覧を含む他のレシピフィールドは、[レシピリファレンス](/ja/docs/recipe-reference)
に記載しています。
